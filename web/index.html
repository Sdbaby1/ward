Ward

Before an agent pays, it asks Ward about the receiver. Ward answers allow, warn, or block, with the reasons. Block never reaches the signer. Warn waits for a person. The agent holds a function-call key scoped to one method on one treasury, so a bypass still cannot move NEAR.

Signals and where they come from

SignalSource
Account ageNearBlocks GET /v1/account/{id}, created.block_timestamp in nanoseconds.

Code changedWard's own code-hash history, plus a NearBlocks receipts page when it contains DEPLOY_CONTRACT.

Prior paymentsThis agent's authorization rows in Supabase, or the memory store.
Shared blocklistWard contract get_target, cached in Supabase. One report warns. Three reports, or an owner confirmation, block.

What the agent key cannot do

  • It can call only pay on the treasury contract.
  • It cannot attach NEAR. The treasury spends its own balance.
  • It cannot transfer, add keys, deploy code, or call withdraw, confirm, or report.
  • Its gas allowance is finite. At zero, the key is dead and topping up the account does not revive it.
  • The contract sees the account, not which key signed. The method list is what keeps the agent out of the owner methods.
